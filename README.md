# 刷题 · Practice

把 Markdown 当题目源文件，导入后变成可随机抽 50 题来刷的纯前端应用。数据全部存在浏览器本地（IndexedDB），离线可用、无需部署后端。

## 快速开始

```bash
# 需要 Node 18 以上
npm install
npm run dev      # http://localhost:5173
npm run build    # 类型检查 + 打包到 dist/
npm run preview  # 预览打包产物
```

端到端自检（需要本机 Edge，开发服务器在跑）：

```bash
npm test         # 单元测试（vitest：解析器 19 个用例 + 示例题库校验）
node scripts/e2e.mjs
```

它会走完「导入 → 题库 → 抽 50 题 → 作答 → 交卷 → 结果 → 错题本 → 练习历史」全流程，把截图写进本地的 `docs/shots/`（已在 `.gitignore` 里，不入库），并收集控制台错误。

## 示例题库

`examples/计算机网络.md` 是 15 道题的示例（单选 7 / 多选 4 / 判断 4），克隆下来先导它试手：

1. 打开 http://localhost:5173
2. 右上角「+ 导入 Markdown」
3. 把 `examples/计算机网络.md` 拖进左侧方框，或复制内容粘贴进去
4. 右侧显示「15 题可导入」后点「导入 15 题」

单元测试会顺带校验这份示例能无错误解析，改坏了跑 `npm test` 就会红。

## 数据存在哪儿

题库、错题、练习记录都存在**浏览器的 IndexedDB** 里，跟着「打开地址」走：

- 用 `http://localhost:5173` 导入的题，换到 `http://127.0.0.1:5173` 或别的端口就看不到了（其实是换了个浏览器存储区）
- 清浏览器网站数据 / 清缓存会把题库一起清掉
- 换一台电脑、换一个浏览器，都是空的

要多人共用一份题库，需要后端；当前版本是刻意不做。

## Markdown 格式

一个文件 = 一个知识库；`##` 开一题；选项写列表；答案和解析写引用块。

```markdown
---
title: 计算机网络基础
tags: [网络, 面试]
---

## 1. TCP 三次握手中，第三次握手的作用是？

- A. 确认双方序列号
- B. 建立连接
- C. 防止旧连接请求
- D. 协商窗口大小

> 答案：A
> 解析：第三次握手让服务端确认客户端收到了自己的 SYN+ACK。
> 难度：2

## 2. 下列哪些协议是应用层协议？

- A. HTTP
- B. TCP
- C. DNS
- D. IP

> 答案：A,C
> 类型：多选

## 3. 交换机工作在数据链路层。

- A. 正确
- B. 错误

> 答案：对
> 类型：判断
```

| 字段 | 写法 | 说明 |
| --- | --- | --- |
| 知识库标题 | front matter `title:` | 缺省用文件名 |
| 标签 | `tags: [网络, 面试]` | 只用于展示与分类 |
| 题干 | `## 题干` | 支持行内 Markdown（`**粗体**`、`` `代码` ``） |
| 选项 | `- A. 内容` | 判断题也要写 `- A. 正确` / `- B. 错误` |
| 答案 | `> 答案：A` 或 `> 答案：A,C` | 判断题可写 `对` / `错` / `A` / `B` |
| 解析 | `> 解析：…` | 可写多行 `>` |
| 难度 | `> 难度：1–5` | 缺省 2 |
| 题型 | `> 类型：单选 / 多选 / 判断` | 不写则按答案与选项自动判断 |

### 宽容到什么程度

同一份 Markdown 可以有很多写法，下面这些都认：

| 想写的 | 认得的写法 |
| --- | --- |
| 分题 | `#` `##` `###` `####` 标题；全篇没有标题时按 `1.` `2.` 编号分题；都没有就当一题 |
| 选项 | `- A. 内容`、`- A、内容`、`A. 内容`、`A：内容`、`(A) 内容`、`- A 内容` |
| 答案 | `> 答案：A`、`答案 A`、`**答案：A**`、`【答案】A`、`正确答案是 B` |
| 多选 | `A,C`、`A、C`、`A C`、`AC`（连写也能拆） |
| 解析 | `> 解析：…`、`解析：…`、`分析：…`、`【解析】…`，可以写多行 |
| 判断题 | 写 `> 答案：对` 就行，选项自动补 `A. 正确 / B. 错误` |
| 题型/难度 | `> 类型：多选`、`> 难度：3`（也可以从答案个数自动判断） |
| 代码块 | ` ``` ` 里的 `##`、`- A.` 不会被当成新题 |

**严格模式：不猜你的意思。** 写法能认就认，但只要“意思”有歧义，一律报错拒收那一题（其它题照常导入），并指出第几行：

- 标成单选却给了多个答案 → 报错（不擅自改成多选）
- 标成多选却只有 1 个答案 → 报错
- 题型写了不认识的词（如“填空”）→ 报错
- 答案不在选项里、选项不足 2 个、缺答案 → 报错

只有“结构能唯一确定”的地方才补全，且一定在预览里提醒你（例如判断题没写选项，自动补 A.正确 / B.错误）。

导入时会**逐行校验**：缺答案、选项不足、答案不在选项里、跨题漏空行等都会在预览面板里报出「第 N 行 + 原因」，可以改完再导。同一知识库内题干重复的题会自动跳过。

## 规则

- **抽题**：先按知识库过滤，`Fisher–Yates` 洗牌后取前 50；不足 50 就全部出题。
- **题型**：单选 / 多选 / 判断。
- **判分**：答案集合完全一致才得分，多选漏选、错选均为 0 分。
- **记录**：每次交卷存一条练习记录；答错的题 `wrongCount + 1` 并记 `lastWrongAt`。
- **错题本**：`wrongCount > 0` 的题自动进错题本，跨知识库汇总；可以按「错得最多 / 最近错 / 按知识库」排、按知识库筛、搜索，单题「标为已掌握」（清零）。
- **错题练习**：从错题池里随机抽 50（不足全出）练；答错 +1，答对 −1（最低 0），也就是“熟悉度”在回升，答对了就慢慢退出错题本。
- **练习历史**：每次交卷留一条记录，按时间倒序列出得分/正确率/用时，可筛知识库；点「看回顾」直接回到那一次的逐题回顾。
- **两种答题模式**：考试模式（交卷后统一看结果）和练习模式（选完立刻显示对错、正确答案和解析；多选点「对答案」揭晓）。模式记在本地，下次进来还是它。
- **抽题策略**：知识库页右上角可切「随机 / 优先没做过 / 优先错题」，对每个知识库的开始刷题都生效。
- **重命名**：知识库名字可以改——知识库卡片上的「重命名」，或在管理页标题旁边点「重命名」。改名会一并更新已有练习记录里存的名字，历史列表不会新旧混着显示。
- **断点续答**：答题过程每隔 300ms 存一次草稿，刷新、关标签页再进同一套题会提示「已恢复上次进度」，也可以「重新抽题」；交卷后草稿自动删除。
- **收藏夹**：刷题页和题库管理里都能点 ☆ 收藏，顶部「复习」页集中列出来，可以一键「收藏练习」。
- **间隔复习**：每道答过的题会排队复习，节奏是 10 分钟 → 1 天 → 3 天 → 7 天 → 15 天 → 30 天；答对往后推一档，答错退回 10 分钟。到点的题出现在「复习」页和顶部徽标里，可以「开始复习」集中处理。

## 离线 / 装到桌面（PWA）

`npm run build` 后产物带 `manifest.webmanifest` 和 Service Worker：用 `npm run preview`（或任何静态托管）打开，浏览器地址栏会出现「安装」，装完就是一个独立窗口的 App，断网也能打开（题库本来就在本地 IndexedDB 里）。

- Service Worker 只在正式构建里注册，`npm run dev` 下不注册，免得改代码被缓存挡住；改了代码看不到效果时，打包预览再看。
- 部署到子路径（比如 GitHub Pages 的 `/practice/`）没问题：`base: './'` 和 manifest 里都用相对路径，Service Worker 的作用域跟着页面走。

## 刷题时的键盘操作

`1`–`4` 或 `A`–`D` 选选项 · `←` `→` 切题 · `Enter` 下一题 · `F` 标记本题。焦点在输入框或按着 Ctrl/⌘ 时不拦截。

## 刻意不做的

- JSON 备份 / 换设备迁移：只打算在单台电脑上用
- 公式渲染（KaTeX）、图片题：题目不含数学公式
- 移动端专门适配：手机上能用（PWA 可安装），但没有为小屏单独设计布局
- 账号、多用户、云端同步：没有后端
