# 刷题网页 · 大纲 v1.0

> 一句话：把 Markdown 当"题目源文件"，导入后变成一个可随机抽 50 题来刷、且能对题库做增删改查的纯前端应用。

## 1. 目标与边界

**做什么**

- 只支持 Markdown 导入（不做 Excel / Word / 图片 OCR）
- 一次练习随机抽 50 题
- 知识库（= 题库）与题目的增删改查
- 作答 → 判分 → 结果回顾 → 错题沉淀

**不做什么（v1）**

- 不做账号 / 多人 / 排行榜
- 不做服务端；纯前端 + 浏览器本地存储
- 不做 AI 出题、不做图片题（先留字段）

## 2. 核心用户流程

```
导入 .md → 解析 → 校验 → 入库 → 选题(50) → 作答 → 交卷 → 结果/错题
                                    ↑
                          知识库管理(增删改查)
```

## 3. Markdown 导入规范

一个文件 = 一个知识库；`##` 开始一题；用 `>` 引用块写答案与解析。

```markdown
---
title: 计算机网络基础
tags: [网络, 面试]
---

## 1. TCP 三次握手的第三次的作用是？

- A. 确认双方序列号
- B. 建立连接
- C. 防止旧连接请求
- D. 协商窗口大小

> 答案：A
> 解析：第三次握手让服务端确认客户端收到了自己的 SYN+ACK。
> 难度：2
```

解析规则（v1）

| 元素 | 识别方式 | 缺失时 |
| --- | --- | --- |
| 知识库标题 | front matter `title`，否则文件名 | 用文件名 |
| 题目 | `##` 标题行 | 至少 1 题，否则拒导 |
| 选项 | `- A.` / `- B)` 列表行 | 无选项视为简答题 |
| 正确答案 | `> 答案：A`（多选 `A,C`） | 报错，不可导入 |
| 解析 | `> 解析：` | 允许为空 |
| 标签/难度 | front matter 或 `> 标签：` | 默认空 / 2 |

**校验是这个功能的价值点**：解析出问题时要给"第 12 行：缺少答案"，而不是整份文件静默失败。

## 4. 数据模型（IndexedDB / Dexie）

| 表 | 关键字段 |
| --- | --- |
| `banks` 知识库 | id, title, description, tags[], createdAt, updatedAt |
| `questions` 题目 | id, bankId, type(single/multiple/judge/short), stem, options[{key,text}], answer[], explanation, tags[], difficulty, sourceLine, createdAt |
| `sessions` 练习记录 | id, bankId, questionIds[], answers{id: string[]}, startedAt, finishedAt, score, durationMs |
| `wrongBook` 错题 | questionId, wrongCount, lastWrongAt, masteredAt |

关系：`banks 1—N questions`；`sessions N—N questions`（用 questionIds 快照，避免改题后历史失真）。

## 5. 页面清单

1. **首页 / 知识库列表**：卡片显示题目数、最近练习、正确率；新建、导入、删除
2. **导入页**：拖拽 → 解析预览（成功 N 题 / 失败 M 条）→ 选择"新建知识库 / 追加到已有 / 覆盖同名" → 确认入库
3. **知识库详情**：题目列表（搜索、标签筛选、分页）、单题编辑、删除、批量删除
4. **刷题页**：单题卡片、进度 3/50、计时、标记、上一题/下一题、交卷
5. **结果页**：得分、正确率、按知识点分布、错题逐题回顾
6. **错题本**：按错误次数排序，可"仅刷错题"

## 6. 抽题算法与边界（已定）

- 基础：`Fisher–Yates` 洗牌后取前 50，等概率、无偏
- 筛选：先按 `bankId` / 标签 / 题型过滤，再洗牌
- 不足 50：**全部出题**（不跨库、不拦路），界面上标注"本题库仅 N 题"
- 题型：**单选 / 多选 / 判断**（判断题 = 两个选项 + 对/错答案）
- 判分：**完全一致才得分**，多选漏选、错选一律 0 分
- 可加权重（P1）：错题 ×2 权重、久未练习优先——用加权抽样而不是简单洗牌
- 同一份试卷内去重；题目被删除后历史记录仍可回看（存快照）

## 7. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite + React + TS | 本地跑起来快，类型能兜住题目结构 |
| 样式 | 手写 CSS（变量 + 深浅色） | 页面量不大，省掉 Tailwind/PostCSS 构建链，主题切换更直接 |
| Markdown | `markdown-it` + 自定义 token 遍历 | 比正则稳，能拿到行号做报错定位 |
| 存储 | IndexedDB（Dexie） | 纯前端、容量大、离线可用；后续换 API 只改 repository 层 |
| 状态 | Zustand | 练习会话状态轻量 |

## 8. 迭代计划

- **P0 骨架**：路由 + 数据层 + 假数据跑通"抽 50 题 → 作答 → 结果"
- **P1 导入**：Markdown 解析 + 校验预览 + 入库
- **P2 管理**：知识库 / 题目 CRUD、搜索筛选
- **P3 沉淀**：错题本、统计、权重抽题
- **P4 打磨**：快捷键（1-4 选项、←→ 翻题）、导入导出 JSON 备份

## 9. 已定决策与剩余风险

**已定**（2026-10-30）

- 题量不足 50 → 全部出题，不跨库补齐
- 题型范围 → 单选 / 多选 / 判断
- 多选判分 → 答案集合完全一致才给分

**风险**

- **Markdown 写法不统一**：提供模板下载 + 容错解析 + 逐行报错
- **题干含代码/公式**：v1 用 markdown-it 渲染行内语法，公式（KaTeX）留到 P3
- **判断题选项**：要求显式写 `- A. 正确` `- B. 错误`，答案写 `对/错` 或 `A/B` 都接受
